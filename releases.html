Every build, and what changed.

Downloads for macOS, Windows and Linux, with a SHA-256 checksum for every file. Penkeep is a local-first application — nothing here phones home, and the installer you download is the whole product.

Verify your download

Builds are not code-signed, so the checksum is your integrity check. Download SHA256SUMS.txt for the version you took, put it beside the installer, and run:

# macOS / Linux
shasum -a 256 -c SHA256SUMS.txt --ignore-missing

# Windows (PowerShell) — compare the output against the line in SHA256SUMS.txt
Get-FileHash .\Penkeep_1.1.1_x64-setup.exe -Algorithm SHA256

macOS will warn that the app is from an unidentified developer — right-click → Open the first time. Windows SmartScreen will flag the installer.

v1.1.1 Latest the multi-folder fix batch 06/08/2026

This patch makes Penkeep behave properly when you have several folders open at once, and clears a batch of sharp edges.

Fixed — multiple folders

  • Search covers every open folder. Cmd+K used to search only the "active" folder and said nothing about the rest. Now every open folder is searched, results name the folder they came from, and a large folder cannot crowd a small one out of the list.
  • Wiki-links work across folders — and prefer the note's own folder. A [[link]] resolves inside the note's own folder first and only then looks at the other open folders; the [[ autocomplete lists files from all of them, own folder first.

Changed

  • Deleting from the sidebar is harder to do by accident. Delete now requires Cmd+Backspace (Ctrl elsewhere), and the confirmation says plainly that the delete is permanent and skips the Trash.
  • Snippets: what you type is a title. The extension is Penkeep's business; names with dots and dates work; saving over an existing snippet warns first; renaming onto another snippet's name is refused instead of destroying it.
  • Six more formatting buttons in the toolbar, and icon buttons that read as buttons again.

Fixed — everything else

  • New and empty documents opened pre-filled with welcome boilerplate, then autosaved it.
  • Plain-text paste pulled every line into its own paragraph.
  • A false "Failed to open file" error after bulk-deleting open files.
  • Backspace in the new-file name box offered to delete the selected file.

v1.1.0 encryption-first storage 03/08/2026

The headline of this release is end-to-end encryption. A note can be encrypted with a passphrase of your own and is stored as .emd: XChaCha20-Poly1305 for the content, Argon2id to derive the key, zstd to compress before encrypting. Encryption is per-file, not per-vault — you choose which notes get it, and there is no master key that opens everything. An unlocked passphrase is held for the session only; when it lapses the note locks again, and the file on disk is encrypted the whole time.

Added

  • Plain-text mode for .txt and .sh. They now open in a raw editing surface that preserves bytes and line breaks exactly. Previously they went through the markdown pipeline, which turned every single-newline line break into a space on save and collapsed the file onto one line.
  • Rescue an encrypted note whose file has gone. If an unlocked .emd is deleted, or its volume unmounts, while you have unsaved edits, the save now offers Retry and Save As… instead of a dead end — your work is in the buffer and used to be stranded there.
  • IPC path-boundary guard. Every path-taking backend command now checks the requested path against a working-set allowlist before touching disk. Defence-in-depth against a compromised webview reading or writing arbitrary files.
  • Save-time guards. A buffer can only be written to the file it was loaded from, and a save that would erase more than 80% of a file asks first.
  • Copy puts markdown on the clipboard, so list markers, headings and emphasis survive a paste into any other editor.
  • Root-header context menu — New File, New Folder, New from Template, Reveal in Finder, Set as Active Root, Close Folder, scoped to the root you right-clicked.

Changed

  • Snippets panel redesigned around copying. Rows show titles; a single click expands a 3-line preview with a copy button; new snippets are created in an inline form.

Fixed

  • Exporting to HTML deleted parts of your document. Any note containing a word merely starting with "on" — only, once, one, online, onto — followed by a link or image came out mangled: "I only agree" with an image below it exported as just "I". Export now runs through a real markdown renderer, so documents come out whole — and tables export for the first time.
  • Exporting a note about security quietly censored it. Documenting an attack — an XSS payload in a code block — got it stripped from the export. Payloads now export exactly as written, rendered as text so an export still can't do anything when opened.
  • A save could write one tab's contents over another tab's file. Content and destination path were independent shared singletons; they are now bound together, and the binding is asserted at the write boundary.
  • Renaming a file from the file tree resurrected the old filename on the next save.
  • Saving a hard-wrapped paragraph joined words together across a soft line break before an inline code span.
  • Frontmatter lost the blank line after its closing ---; image titles were dropped on save; wiki image embeds were corrupted in untitled documents.

Known limitations

  • Builds are unsigned and un-notarized on every platform.
  • Touch ID ships disabled. The Keychain retrieval gate is implemented, but macOS rejects the biometric Keychain ACL on an unsigned binary. It turns on once signing lands.
  • The encryption orphan-finder and the in-app Help tab are not built yet; the orphan-finder's button is visible but disabled.
  • The app icon is still a placeholder.
